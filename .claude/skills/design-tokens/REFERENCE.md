# Design Tokens — Reference

Full layer definitions for the 3-layer system: **Primitive → Semantic → Responsive**. Every layer aliases the one below it — nothing skips a layer, nothing hardcodes a raw value where a token already exists for it.

Adapted from a Figma Variables token generator (Brand → Alias → Mapped → Responsive); this version drops Figma's brand-theme-swap "Alias" layer (no project here needs multi-brand mode switching) and targets plain CSS custom properties instead of Figma Variables/Collections/Modes.

## Layer 1 — Primitive (raw values, no meaning yet)

### Color groups

One 11-step scale per hue actually needed, generated by `scripts/generate-scale.mjs`:

| Group | Source | Steps |
|---|---|---|
| `{primary-hue}` (e.g. `purple`) | the given primary color | 50, 100, 200, 300, 400, 500, 600, 700, 800, 900, 950 |
| `{secondary-hue}` (e.g. `pink`) | the given secondary color, if any | same 11 steps |
| `green` | success — conventional unless the project already defines one | same 11 steps |
| `red` | error — conventional unless the project already defines one | same 11 steps |
| `yellow` | warning — conventional unless the project already defines one | same 11 steps |
| `grey` | neutral | same 11 steps **+ `white` + `black`** |

Default hues when success/error/warning/neutral aren't already defined: green ≈ 142°/45% sat, red ≈ 4°/72% sat, yellow ≈ 38°/92% sat, grey = same hue as primary at 4–8% saturation (a brand-tinted grey). Neutral's grey runs through the same scale script, then add flat `#FFFFFF`/`#000000` for `white`/`black`.

Naming: `--color-{hue}-{step}`, e.g. `--color-purple-500`, `--color-grey-white`. Never name a Primitive color group by role (`primary`, `secondary`) — that's the Semantic layer's job.

### Spacing, radius, size scales (px)

A 4px-grid scale from 0–128, plus one exception step (10) for the odd in-between gap real UIs need. Keep **spacing** (layout gaps) and **radius** (corners) as separate token groups even though they share the same numbers — they're different decisions that happen to reuse a scale:

```
--spacing-0  --spacing-4  --spacing-8  --spacing-10 --spacing-12 --spacing-16
--spacing-20 --spacing-24 --spacing-28 --spacing-32 --spacing-36 --spacing-40
--spacing-44 --spacing-48 --spacing-52 --spacing-56 --spacing-60 --spacing-64
... up to --spacing-128
```

Same steps for `--radius-*`. A separate `--size-*` scale (also 4px-ish grid, finer at the low end) is reserved for typography — see below. If a value is needed between two steps, add the step to the scale; never type a one-off raw number.

### Type primitives

- `--font-primary`: the given font family. Add `--font-secondary` only if the product genuinely needs a companion face (e.g. primary is display-only) — don't add one speculatively.
- **Check the font's real available weights before creating a weight token.** Don't assume Regular/Medium/Semibold/Bold exists — check the font's actual `@font-face` declarations or, for a web font, the Google Fonts API. Create `--font-weight-{name}` only for weights that actually exist:

  | Token | Numeric weight |
  |---|---|
  | `--font-weight-thin` | 100 |
  | `--font-weight-extralight` | 200 |
  | `--font-weight-light` | 300 |
  | `--font-weight-regular` | 400 |
  | `--font-weight-medium` | 500 |
  | `--font-weight-semibold` | 600 |
  | `--font-weight-bold` | 700 |
  | `--font-weight-extrabold` | 800 |
  | `--font-weight-black` | 900 |

  If a weight a component needs (typically Regular/Medium/Semibold/Bold) is missing, fall back to the nearest weight the font actually ships and record the substitution — don't fabricate the missing weight or silently substitute a system font.
- Type size scale: `--size-{step}` in px, spanning roughly 10–128, finer-grained at the low end (10, 12, 14, 16, 18, 20, 24, 28, 32...) than the spacing/radius scale, since body-text sizes cluster tightly.

## Layer 2 — Semantic (Light/Dark, aliases Primitive only)

Four groups — Surface, Text, Icon (identical mapping to Text — icons follow text color roles 1:1 by default), Border. Every token aliases a Primitive color token via `var(--color-...)`, switched by `[data-theme="dark"]` (or `prefers-color-scheme` as the default before an explicit theme is set).

**Surface**

| Token | Light | Dark |
|---|---|---|
| `--surface-page` | `--color-grey-white` | `--color-grey-950` |
| `--surface-primary` | `--color-grey-50` | `--color-grey-900` |
| `--surface-secondary` | `--color-grey-100` | `--color-grey-800` |
| `--surface-action` | `--color-{primary}-500` | `--color-{primary}-500` |
| `--surface-action-hover` | `--color-{primary}-700` | `--color-{primary}-700` |
| `--surface-disabled` | `--color-grey-300` | `--color-grey-300` |
| `--surface-success` | `--color-green-50` | `--color-green-800` |
| `--surface-error` | `--color-red-50` | `--color-red-800` |
| `--surface-warning` | `--color-yellow-50` | `--color-yellow-800` |

**Text** (Icon reuses this table verbatim, prefixed `--icon-*` instead of `--text-*`)

| Token | Light | Dark |
|---|---|---|
| `--text-primary` | `--color-grey-900` | `--color-grey-white` |
| `--text-secondary` | `--color-grey-700` | `--color-grey-50` |

**Border**

| `--border-primary` | `--color-grey-300` | `--color-grey-700` |
| `--border-secondary` | `--color-grey-200` | `--color-grey-800` |

```css
:root {
  --surface-page: var(--color-grey-white);
  --text-primary: var(--color-grey-900);
  /* ... */
}
[data-theme="dark"] {
  --surface-page: var(--color-grey-950);
  --text-primary: var(--color-grey-white);
  /* ... */
}
```

## Layer 3 — Responsive (Desktop/Tablet/Phone, aliases Primitive only)

Breakpoint reference: Desktop 1440px, Tablet 1024px, Phone 393px — override only if the product's real breakpoints are known to differ.

Every Responsive token aliases a Primitive `--spacing-*` or `--size-*` step per breakpoint — never an independent number, so bumping a Primitive step updates every Responsive token built from it:

```css
:root {
  --jumper-lg: var(--spacing-64); /* desktop default */
  --heading-h1: var(--size-96);
}
@media (max-width: 1024px) {
  :root {
    --jumper-lg: var(--spacing-48);
    --heading-h1: var(--size-64);
  }
}
@media (max-width: 393px) {
  :root {
    --jumper-lg: var(--spacing-24);
    --heading-h1: var(--size-40);
  }
}
```

Name section-spacing tokens `--jumper-*` and heading-size tokens `--heading-{level}` / `--heading-{level}-lineheight` (line-height aliases the next Primitive size step up from the matching font-size step). Only add a breakpoint-driven behavior flag (e.g. a "does nav collapse" boolean) for behavior the product genuinely has — don't fabricate one for every possible layout switch.

## DESIGN.md handoff

`impeccable document`'s `DESIGN.md` format (see `.claude/skills/impeccable/reference/document.md`) expects a flat frontmatter: `colors`, `typography`, `rounded`, `spacing`, `components`. Populate it from this system's **Semantic** layer (not Primitive) — `DESIGN.md` wants role-based values a new-screen generator can reach for directly:

```yaml
colors:
  surface-page: "var(--surface-page)"
  text-primary: "var(--text-primary)"
  # ...one entry per Semantic token actually used
typography:
  body:
    fontFamily: "var(--font-primary)"
    fontSize: "var(--size-16)"
```

This means `impeccable`'s existing hook and drift-audit read the output of this skill with zero extra glue — they were built to read `DESIGN.md`, not a new artifact format.

## Do not

- Add a 4th layer, or extra modes beyond Light/Dark and Desktop/Tablet/Phone.
- Let a Responsive or Semantic token alias a raw hex/px value, or skip straight to a Primitive value two layers down without an intermediate alias existing for a reason.
- Name a Primitive color group by role — that's Semantic's job.
- Generate a duplicate scale for a hue that already has one.
- Invent success/error/warning/neutral hues without checking whether the project already defines them.
- Fabricate a breakpoint-behavior flag the product doesn't actually have.
- Store a raw px number in Responsive tokens or text styles — every size aliases a Primitive step; add a new Primitive step if one is missing instead of typing a one-off.
- Assume a font has Regular/Medium/Semibold/Bold — check the family's real available weights first.
- Build the `DESIGN.md` handoff before the CSS layers exist — it documents them, it doesn't come first.
